## Verificarea numerică și toleranțele

- **Diferențe finite** (în F64, h = 1e-6, pe 5 elemente: `emb_token`, `in_proj_weight`, `mlp.0.weight`, `ln1.weight`,
  `ln.bias`): se potrivesc cu gradientul analitic la toleranța relativă **1e-5** — trece. Gradientul F32 față de cel F64:
  ‖Δ‖ ≤ 1e-4 · ‖g‖ pe fiecare tensor — trece.
- **Primul pas recalculat de mână** după formulele din fișă (SGD; AdamW cu tăiere și corecția de bias) = PyTorch
  (rtol 1e-6, atol 1e-7) — trece.
- **Gradientul exportat = gradientul PyTorch**, exact — trece.
- **Cât diferă 1 fir față de 16 fire** (aceeași mașină; alt procesor n-am avut):

| Ce | Mic | #513 | Recomandat în fișă |
|---|---|---|---|
| eroarea, relativ | 1,1e-7 | 6,5e-6 | ≤ 1e-5 |
| gradient pas 1, absolut | 3,6e-7 | 2,7e-6 | ≤ 1e-5 |
| gradient pas 1, ‖Δ‖/‖g‖ pe tensor | 2,1e-7 | 7,0e-4 | ≤ 1e-3 |
| greutăți SGD, absolut | 1,2e-7 | 1,2e-7 | ≤ 1e-6 |
| greutăți AdamW după pasul 1, absolut | 1,8e-11 | 8,0e-6 | ≤ 1e-4 |
| greutăți AdamW după pasul 10, absolut | 8,5e-6 | 1,0e-5 | ≤ 1e-4 |

  La #513 doar 1,3 % din elementele gradientului ies identice bit cu bit între 1 și 16 fire, deci OS-ul nu va da „bit cu
  bit” aceleași numere; comparația trebuie făcută cu toleranțe. La AdamW toleranța e mai largă (până la 2 · lr = 1e-4),
  fiindcă la elementele cu gradient aproape zero o rotunjire poate întoarce direcția pasului. Măsurătorile:
  `lucru/cascada/S132_proba/dif_mic_1_16.json`, `dif_513_1_16.json`.
